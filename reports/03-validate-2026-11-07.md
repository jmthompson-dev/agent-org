## 1. Summary

- **Routing works as designed.** Level 0 and Level 1 prompts stayed in the main thread with no agents. Level 2 prompts loaded `deliver`, called only the PM, and stopped for approval (2/2 runs). `/agent-org:pm` forced escalation. User-only skills are invisible to the model but work when typed. - **Blocker (D6): the intent file can't be saved under `~/.claude/`.** Claude Code treats every path under `~/.claude/` as a *sensitive file*. - **D3 is now concrete.** The `Agent` calls ran asynchronously (background) by default. Every subagent report came back as a `<task-notification>` turn that fired `UserPromptSubmit` and matched trigger groups. So the redundant nudge fires on **every** escalation, not rarely. The payload's key set is identical to a typed prompt, but the prompt text starts with `<task-notification>`. That gives a usable filter.
- **D18 is answered.** `PreToolUse` payloads carry `agent_id` and `agent_type` (for example `agent-org:full-stack-developer`) **only** for subagent tool calls. Main-thread calls don't have them. So QA's `Edit` can be scoped by `agent_type` in a Phase 4 guard.

## 6. Phase 4 inputs

### Hook payload key sets (D3)

There was exactly **one** `UserPromptSubmit` key set across all 20 logged events: `cwd, hook_event_name, permission_mode, prompt, prompt_id, session_id, transcript_path`. No field tells a typed prompt from anything else.

Non-typed `UserPromptSubmit` events **did** occur, 7 of them:
- **Where:** 4.5a, 4.5b, 4.6 (×2), 4.8 and 4.10.
- **What:** each time, a background subagent finished. Its report came back as a user turn, which the transcript records with `origin: {"kind": "task-notification", …}` and content beginning `<task-notification>`.
- **Same text as the hook saw:** the hook's logged `promptLength` equals that content's length exactly (8722 and 12156 in 4.5a/b). So the hook's `prompt` is the notification text.
- **Groups matched:** the reports mention auth, secrets, deploy and so on, so they matched 1–5 groups and re-injected the nudge.
- **Filter:** none of `origin`/`isMeta` reaches the hook payload. The usable filter is **`prompt.startsWith('<task-notification>')` → no nudge**. I didn't log prompt text, so the prefix comes from the transcript and the exact length match, not from the hook itself.
- **Cross-session messages:** none occurred. Not simulated.

Why it's every escalation: the `Agent` calls had no `run_in_background` input, but each returned "Async agent launched successfully". The main turn ended, and the result came back as a notification turn. This is the default behavior in this build. I didn't find which setting controls it (see §10).

### `PreToolUse` agent identity

- **`--settings` merges hooks for one session:** verified in a Haiku probe run (session `2e9ebb1f`). The probe `PreToolUse` hook fired, and the plugin's `SessionStart` and `UserPromptSubmit` hooks still fired too. `~/.claude/settings.json` was never touched.
- **What 4.6 logged:** the probe recorded 16 calls.
  - Main-thread calls (Bash, Agent) had the keys `cwd, effort, hook_event_name, permission_mode, prompt_id, session_id, tool_input, tool_name, tool_use_id, transcript_path`.
  - Subagent calls had the same keys **plus `agent_id` and `agent_type`**. Values seen: `agent_type: "agent-org:full-stack-developer"` (agent_id `a366c2ae…`) and `"agent-org:information-security-architect"` (agent_id `a9596a81…`).
- **Finding:** subagent calls **can** be told apart from main-thread calls. `agent_type` is present and names the plugin agent; it's absent on the main thread. A Phase 4 guard can limit `agent-org:quality-assurance-architect` `Edit`/`Write` to test paths by `agent_type`.

Also for Phase 4: Bash commands that Claude Code considers read-only ran without a matching rule. In 4.4, `cat …; ls .probe` and `git log … | head; ls -la` ran with only `Bash(git log*)` granted. In 4.9 a `for … cat` loop was denied. Built-in read-only auto-approval sits beside the explicit rules.

## 9. Failures and proposed fixes

1. **F1: the intent path is unwritable (D6).** `~/.claude/**` is a protected sensitive path. CLI allow rules plus `--add-dir` don't get past it. Headless it's a hard deny; interactively it would prompt on every save and every approval-log update.
   - **Fix (decisions.md D6, then 02-generate.md → deliver skill and rule card):** move intents outside `~/.claude`, for example `~/.agent-org/intents/<repo>/`. It's still cross-OS and outside the target repo.
   - **Phase 4 alternative:** test whether a user-settings `allow` rule for `~/.claude/intents/**` is honored. CLI rules weren't, so I'd expect the same.
2. **F2: no saved intent, but implementation went ahead (D6).** After "Approved." the main thread implemented with no intent on disk. It was candid about it, but D6 says Level 2+ needs an *approved intent file*.
   - **Fix (02-generate.md → deliver step 3/5):** "If the intent can't be saved, stop and tell the user; don't implement until it's saved or the user explicitly waives the file."
3. **F3: Level 1 skips the plan line and tests (D5).** This happened in 2/2 runs.
   - **Fix (02-generate.md → rule card):** make Level 1 imperative and concrete. For example: "Level 1: before your first edit, write one line: 'Plan: …'. After editing, run the repo's test command (e.g. `npm test`) and report the result." The current "One-line plan, then do it with focused tests" reads as descriptive.
4. **F4: the nudge fires on every subagent report (D3).** Because agents run async, each report is a `<task-notification>` prompt.
   - **Fix (02-generate.md → escalate.mjs; record in decisions.md D3):** return no nudge when `prompt.trimStart().startsWith('<task-notification>')`. Keep logging key names. D3's "accept the redundant nudge" should become "filter task notifications"; it's no longer rare.
5. **F5 (minor): the PM uses role names, not agent ids (D2).** In 4.5a the PM wrote "Software engineer (implementer)" and "Security reviewer (InfoSec)" in the Agent column. The main thread mapped them correctly, but that relies on a guess.
   - **Fix (02-generate.md → deliver intent template):** change the column header to `Agent (agent-org:<id>)` and say ids are mandatory. That's a runtime binding, not a persona edit.
6. **F6 (doc): the D14 wording.** The synced `engineering`/`design` plugins still appear in `plugin list`, disabled.
   - **Fix (decisions.md D14):** change "confirm they're gone" to "confirm they're disabled".
