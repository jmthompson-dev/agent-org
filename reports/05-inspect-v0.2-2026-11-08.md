# Phase 5: Inspect for v0.2 (2026-11-08)

Claude Code 2.1.319 (the latest release: the changelog's top entry is 2.1.319, November 6, 2026), macOS, Node 24.18.0. Installed: `agent-org` 0.1.0 pinned to `v0.1.0` from GitHub (`claude plugin list` shows no `Read from:`); the user's 102 ask rules and one scoped allow; `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` unset. Six live probe runs cost **≈ $0.19**. The only repo file written is this report.

## 1. Summary

- **Feasible, with three changes.** Every hook v0.2 depends on exists and behaves as the plan needs: `Stop`/`SubagentStop` can block once and force a continuation, the reason reaches the right agent, `agent_id` tells parallel instances apart, and an id chain links each dispatch to its result and model. Teams stay docs-only.
- **B3's collision definition is wrong for the case that matters.** When two parallel agents edited the same line, the second `Edit` was **refused** ("File has been modified since read… Read it again"). The agent re-read the file, didn't overwrite it, and reported "Not changed". No hook saw the refused attempt: no `PreToolUse`, no `PostToolUseFailure`. So "file changed by two agents" never fires. The collision shows up only as a refused edit in the subagent transcript, plus the agent's own report. B3 has to scan for that too, and the specialists have to report it as BLOCKED.
- **A1 works, but needs four corrections:**
  - Read the final text from `last_assistant_message`; the transcript lagged and didn't contain it at stop time.
  - Count only `type:"assistant"` transcript entries; request blobs duplicate every tool call.
  - Skip relayed or retracted claims, which caused one false-positive block in P3.
  - **Citation check:** on macOS, Glob and Grep are absent by default, so reads arrive as Bash `cat`/`grep`/`sed -n`. The check has to parse Bash too. It holds for invented files only, as the plan already says.
- **The audit chain needs a lock and a head record.** Without a lock, 28 of 40 parallel appends broke the chain; with a `mkdir` lock, 0 did. The chain alone can't detect an edit to its last line or a deleted tail. Verifying 200k lines takes 0.74 s, so check incrementally from a checkpoint.
- **Session identity is solid for D4.** `session_id` is in every payload. It's unchanged across resume and `/compact` (observed) and new after `/clear` (docs). The teams-fallback gaps (hooks and identity inside teammates, teammate transcripts) can only be settled interactively; §6 F7 has the steps.

- Installed v0.1 (`agent-org@agent-org` 0.1.0): `UserPromptSubmit` escalate.mjs, `SessionStart` session-start.mjs (rule card), and `PreToolUse` guard.mjs (`Bash|PowerShell|Edit|Write`).

**No observed behavior was caused by a v0.1 hook.** The guard returned nothing on every Edit and Bash call. The escalate hook matched no triggers, so no nudge. The rule card was injected at each `SessionStart`.
