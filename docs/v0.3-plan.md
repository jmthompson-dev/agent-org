# agent-org v0.3.0 plan — memory

## Context
- **Builds on:** v0.2.0, tagged at `616d43a`. Reuse what v0.2 already has: the hash-chained audit log (D27), the `SubagentStop` hook and report contract (D25), and `plugin/hooks/lib/` (`repo.mjs`, `state.mjs`, `lock.mjs`, `audit.mjs`).
- **Read first:** `docs/decisions.md` (D1–D30), `docs/v0.2-plan.md`, and `reports/05`–`06b`.
- **Rules that still hold:**
  - Every plugin change is mirrored in `prompts/02-generate.md`.
  - Develop with `claude --plugin-dir ./plugin`.
  - Each phase prompt ends "stop and report".
  - Release with the interactive checklist (`docs/release-checklist.md`).

## Goal
An optional memory module: lessons learned from **reviewed** work are kept between sessions and found again when relevant, without adding an agent, leaking sensitive data, or turning stale lessons into false facts.

## Decisions

### M1. No Librarian persona (preserves R1)
Filing is a script. It makes one cheap model call only when a proposal matches an existing note, to decide merge, supersede or keep both. The script does every write.

### M2. Storage
- Root: `~/.agent-org/memory/`. Never inside any repo, never under `~/.claude/`.
- `global/` holds how the user works and persona lessons. `projects/<project-key>/` holds per-project lessons. `inbox/` holds proposals. `archive/` holds retired notes.
- Each of `global/` and every project folder has an `INDEX.md` with one-line summaries.
- **Project key (open, settle in Inspect):** `lib/repo.mjs` names a repo by the basename of its top level (D6). Two repos with the same basename would share memory. Proposed: key on the normalized `origin` remote (ssh and https map to the same key). With no remote, fall back to a hash of the top-level path. With several remotes, prefer `origin`. Store the D6 repo name in each note's header so notes can be joined to the audit log and intents.
- Refuse to write if the memory root is inside a git work tree (for example a dotfiles repo).

### M3. Capture
Add an optional `lessons:` field to the specialist report contract. The existing `SubagentStop` hook extracts it. Nothing else changes in persona instructions.

### M4. Content rule and screening, at proposal time
- Lessons are about code and process only. No customer, personal or shipment data.
- Before anything reaches `inbox/`, two checks run:
  - a regex blocklist for credentials, tokens, API keys and secrets
  - one Haiku yes/no call: does this contain personal or customer data?
- Reject a proposal that fails either check.
- Internal hostnames are allowed.
- Document honestly that this is a floor, not a guarantee.
- **Verify in Inspect:** whether a Claude Code prompt-based hook can run the Haiku check with no custom code.

### M5. Filing
Filing runs lazily: at the next `SessionStart`, or through an explicit command. It never runs from `Stop`, which fires every turn, or `SessionEnd`, which may be killed.
1. **Take the filing lock.** This is not `lib/lock.mjs` as configured: that lock goes stale at 2s and gives up after 3s, then proceeds *unlocked*, which is right for hooks but wrong for a job with a model call. The filing lock records a PID and start time, treats a lock as stale only when its PID is dead or it exceeds a TTL of several minutes, and **fails closed**: if the lock is held, skip filing; the inbox waits for the next run.
2. Drop any proposal whose work did not pass review according to the audit log.
3. Match each proposal on topic, `applies_when` and scope. With no match, file it. With a match, the model call decides merge, supersede or keep both.
4. Update `INDEX.md`, then release the lock.

### M6. Note format
- **YAML header:**
  - `topic`, `applies_when`, `scope`
  - `repo` (the D6 name)
  - `evidence`: commit SHA plus `file:line`
  - `source`: session and intent, plus the review outcome
  - `created`, `last_used`, `use_count`
  - `status`: `active`, `superseded` or `archived`
  - `superseded_by`
- **Body:** short. Short snippets go inline; longer examples go in a linked sibling file.

### M7. Lessons are leads, not facts
The rule card and every runtime binding say: a lesson is a lead. Re-verify it against the current code before acting on it. This ties into the D25 citation rules.

### M8. Loading
`SessionStart` injects only `global/INDEX.md` and the current project's `INDEX.md`. Both are under a hard size cap, and the least-used lines are cut first.

### M9. Search
- **Skill:** a `memory-search` skill plus script.
- **Query:** filter on header fields first (project, topic, `applies_when`, `status: active`), then search text with ripgrep.
- **Output:** for the top 3–5 results only, the header, 1–3 matching lines and the path.
- **Usage counting:** a `PostToolUse` hook on `Read` of any note path does the counting, so direct reads count too, not just reads through the script.

### M10. Supersede and cleanup
- Never overwrite a note. The old note gets `status: superseded` and a pointer to its replacement.
- Cleanup moves superseded notes, and notes unused for 60+ days, to `archive/`.
- Nothing is ever deleted automatically.

### M11. Toggle
One switch, in `~/.agent-org/config` or an env var. When memory is off, the memory hooks do nothing. The plugin ships its own hooks, so nothing is merged into user settings.

### M12. No vector database
Files, indexes and the search skill only.

## Eval harness
- **Paired tasks:** a seeding task that should produce a lesson, followed by a later task that benefits from it.
- **Arms:** several runs with memory on and several with it off.
- **Measures:** cost, turns and pass rate.
- **Isolation:** evals use their own memory root, never `~/.agent-org/memory/`.

## Phases
1. **`07-inspect-v0.3.md`** (read-only, cost-gated probes): verify every unverified capability above. Mark each VERIFIED or UNVERIFIED with a URL or observed output.
2. **Generate:**
   - Update `02-generate.md` and regenerate.
   - Add decisions D31+ for M1–M12.
   - Bump the version to 0.3.0.
3. **`08-validate-v0.3.md`** checks:
   - project-key fallbacks
   - startup loads only the capped indexes
   - search results are compact
   - the blocklist and the Haiku check reject sample secrets and personal data
   - unreviewed work is never filed
   - supersede works
   - archive cleanup works
   - two-session lock contention (one files, one skips)
   - recovery from a crashed lock
   - the toggle turns memory on and off
   - nothing is written inside any git work tree
   - the paired eval
   - v0.2 regression
4. **Release v0.3.0** with the interactive checklist.

## Success criteria
v0.3 succeeds if:
- the paired eval shows a measurable gain with memory on
- nothing sensitive or unreviewed is ever filed
- no note is lost without an archive copy
