# agent-org v0.2.0 plan

## Requirements v0.2 must meet

| # | Requirement | v0.1 status |
|---|---|---|
| R1 | Minimum effective agents. Right-sized, not few: one agent for a one-piece job, parallel agents when the job splits. | Met |
| R2 | Little information in, blocking questions back, then the job gets done | Met (single task) |
| R3 | Auditing: a trustworthy record of who did what, and independent review where it's warranted | Partial |
| R4 | Hallucination prevention **at every level, 0–3** | Partial (instruction-only, Level 2+ only) |
| R5 | Agents work in parallel | Not met |

## Design

### A. Hallucination prevention at every level (R4)
The principle: a claim needs evidence, and the check scales with the level. Agents are added only where independence is needed (R1).

| Level | Grounding | Verification | Extra agents |
|---|---|---|---|
| 0 | Claims about code cite `file:line` actually read this session. External facts get a source or are marked unverified. Never invent APIs, flags or config keys; grep or read before naming one. | Claim-evidence hook (A1) | none |
| 1 | As Level 0. Read the code before editing. Run the tests after. | A1, plus a required test run if the repo has tests | none |
| 2 | As Level 1, plus the PM grounds the intent in files it actually read | A1 on the main thread **and** on every specialist report (A2). The main thread re-verifies: reruns the tests itself, and checks that the reported changed files match the actual `git diff`. | none beyond the assigned specialists |
| 3 | As Level 2 | Everything above, plus **one** independent auditor agent that reproduces the key claims before VERIFIED | +1 auditor |

**A1. Claim-evidence hook (deterministic, no agent).**
- Runs as a `Stop` hook for the main thread and a `SubagentStop` hook for specialists. It reads the transcript.
- It scans the final message for verification claims, such as "tests pass", "I ran", "build succeeds", "verified", "no errors", or "N/N passed".
- It checks that a matching tool call exists in the turn and actually succeeded.
- If a claim has no evidence, it **blocks the stop once** with a reason ("claim 'tests pass' has no test run in this turn: run it or retract it"). On the second attempt it allows the stop but appends a warning, to avoid loops.
- It's fail-open and never logs content.

**A2. Report contract check.** Specialist reports must include outcome, the commands run with their exit status, and changed files. The `SubagentStop` hook flags any report missing those, and any "PASS" with no command evidence.

**A3. Grounding rules.** Add grounding rules to the `SessionStart` rule card, kept short, and to every runtime binding: cite read files, never invent identifiers, and mark anything unverified as such.

### B. Parallel execution (R5) that stays minimal (R1)
- **B1.** The PM marks tasks as parallel **only** when they own disjoint files or directories. The intent assignments table gets an "Owns" column. If files overlap, the tasks run sequentially.
- **B2.** Parallel specialists run with `isolation: worktree`.
- **B3.** A merge step in `deliver`. After all parallel reports arrive, the main thread integrates the worktree changes, resolves conflicts (or stops and asks), then runs the full verification once on the merged result.
- **B4.** Agent teams stay off (D7). Background subagents plus worktrees cover it.

### C. Auditing (R3)
- **C1. A model-independent audit log.** Hooks on `PreToolUse` (Agent) and `SubagentStop` append to `~/.agent-org/audit/<repo>.jsonl`, recording: timestamp, session, intent path, agent id, model, dispatch or result, outcome, exit status of claimed commands, and any A1/A2 flags. Never content.
- **C2.** The intent file stays the human-readable record. The audit log is the record the model can't edit. Hooks write it directly, not through tools.
- **C3.** Independent review stays proportional. QA and InfoSec join when triggers fire, and the auditor joins at Level 3. R1 is preserved.

### D. Scope-growth protection (keeps the levels honest mid-task)
- **D1. File counter.** If the main thread (no `agent_type`) edits more than about 3 distinct files in a session with no APPROVED intent for the repo, the guard asks: "This job has grown past Level 1. Approve to continue, or escalate with agent-org:deliver."
- **D2. Risky paths.** A main-thread edit to migrations, CI workflows, IaC/k8s/helm or auth code with no APPROVED intent gets the same ask on the first file.
- **D3.** It always uses `ask`, never `deny` or `allow`, and fails open. State lives in `~/.agent-org/state/`, keyed by `session_id`. Specialists are exempt.
- Decide and document how an intent is matched to the current work: repo, plus base commit or date.

### E. Out of scope for v0.2
- **Autonomous commits after approval.** That needs a deliberate permission design, since ask rules can't be conditional. Revisit in v0.3.
- **Trimming unused personas.** Revisit with usage data.
- **Scoping QA's Bash.** Revisit only if it's seen in practice.

## Phases (each prompt ends "stop and report")
1. **`05-inspect-v0.2.md`:** verify every capability the design depends on, before anything is built.
2. **Update `02-generate.md`,** then regenerate. Add decisions D25–D29 (hallucination at every level, parallel worktrees, audit log, scope-growth guard, Level 3 auditor). Bump the version to 0.2.0.
3. **`06-validate-v0.2.md`** (live, cost-gated, scratch repo), with these acceptance checks:
   - **Level 0:** a question whose answer would tempt the model to invent an API. It cites `file:line` or says it's unverified.
   - **Claim hook:** a Level 1 run where the model claims tests pass without running them. A1 blocks it once, and the model runs or retracts.
   - **Level 2:** a specialist report with a false "PASS". A2 flags it, and the main thread's re-verification catches it.
   - **Parallel (the headline test):** one job with three genuinely separate parts (backend endpoint, frontend page, docs), given as a one-line description. Expect blocking questions, approval, three specialists in separate worktrees at the same time, a clean merge, verification on the merged result, and no agent that wasn't needed.
   - **Audit:** the audit log has every dispatch and result, with correct models and outcomes, for that job.
   - **Scope growth:** a "small" task that sprawls to 4+ files trips D1; a first edit to a migration trips D2.
   - **Level 3:** exactly one auditor agent, and it reproduces the key claim.
   - **Regression:** the v0.1 checks for blocking questions, roster, Status sequence and guard.
4. **Release v0.2.0.**

## Success criteria
v0.2 succeeds if the parallel headline test passes end to end, false verification claims get caught at every level, and the agent count never exceeds what the job needs.
